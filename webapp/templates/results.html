Technical Implementation Details

5-Year Data Window

We use 5 years of daily Bitcoin data (2020-2025) instead of 10 years. Testing showed that recent data is more predictive than distant history due to market regime evolution.

See: 5y vs 10y Comparison Study

Return-Based Prediction

Critical innovation: We predict percentage returns, not absolute prices. This eliminates systematic bias in tree-based models that cannot extrapolate beyond training data.

Formula: predicted_price = current_price × (1 + predicted_return)

58 Engineered Features

Technical indicators (RSI, MACD, Bollinger Bands), lag features, rolling statistics, sentiment data (Fear & Greed Index), and interaction features.

Raw OHLCV data → 58 features → Return targets

✅ Rigorous Testing

Chronological split: 70% train, 15% validation, 15% test. No data leakage. Test set contains only future data never seen during training.

Current test set: {{ xgboost_results[0].test_samples if xgboost_results|length > 0 else 245 }} samples

📈 R² Near Zero is Normal

R² ≈ 0 is expected for crypto returns due to high noise and random walk behavior. Our models achieve R² close to 0, which is optimal (not negative like Random Forest).

Primary metrics: MAPE and Directional Accuracy

🚀 Future Enhancements

Planned improvements: Ensemble predictions (XGBoost + LightGBM + CatBoost), market regime detection, time-weighted training, rolling window optimization.

Expected improvement: 5-10% better robustness

Why Random Forest Failed

The Problem

Severe Overfitting: R² = {{ "%.2f"|format(random_forest_stats.worst_r2|default(0)) }} on 7-day predictions (worse than predicting the mean)

Poor Directional Accuracy: {{ "%.1f"|format(random_forest_stats.avg_directional|default(0)) }}% average (worse than random 50%)

Highest MAPE: {{ "%.2f"|format(random_forest_stats.avg_mape|default(0)) }}% average ({{ "%.1f"|format(random_forest_stats.relative_mape_increase|default(0)) }}% worse than XGBoost's {{ "%.2f"|format(xgb_summary.avg_mape|default(0)) }}%)

Cannot Extrapolate: RF averages training outputs, fails when prices exceed training range

Why It Happens

Non-stationary data: Bitcoin price dynamics change over time

High noise: Crypto markets are extremely volatile with low signal-to-noise ratio

Return-based targets: RF struggles with small returns centered around 0

Limited expressiveness: Decision trees cannot capture complex patterns as well as gradient boosting

Conclusion: For cryptocurrency prediction, gradient boosting models (XGBoost, LightGBM, CatBoost) are significantly superior to Random Forest. Always prefer gradient boosting for financial time series with high volatility.
